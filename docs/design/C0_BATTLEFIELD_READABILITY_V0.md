# C0 Battlefield Readability V0

## 目标与边界

本切片只修复 C0 战场的空间可读性、命令焦点和任务目标表现。它不修改
`BattleRequest → BattleSession → BattleResult → BattleResultApplier` 的权威
事务，不改变固定 tick、伤亡、城门、敌军、奖励、退出或返回规则。

当前仍是 Graybox。此次通过自动测试与 AI GUI smoke 只能证明表现层能读取真实
状态且可操作，不能代替用户对路线意义、节奏、命令手感和任务可读性的实体体验。

## 直接诊断

旧场景把战斗状态直接拼成原始文本：

- 两条路线只是长色块，敌军没有独立可见对象；
- 小队只是不可点击的数字方块；
- 三支小队各自复制一套命令按钮，没有单一选择焦点；
- 粮车、搜索区和撤离区只有文字进度，没有战场投影；
- `RESERVED`、`Tick` 等开发枚举占据玩家信息层。

因此底层状态和事务成立，但玩家无法从画面建立“我方从哪里来、敌军在哪里、当前
接敌对象是谁、任务目标处于什么危险”的空间关系。

## 只读表现模型

`BattlePresentationModel` 是 `RefCounted` 纯投影：

```text
BattleRequest + BattleSession + MissionDefinition + selected_squad_id
→ title / phase / routes / squads / objective
```

它只调用现有只读快照接口或读取临时会话字段，不推进 tick、不下达命令、不写任务
目标、不发信号，也不持有第二份 BattleSession。选择状态只存在于
`C0BattleGraybox` 的 UI 内。

敌军没有权威移动坐标，因此 V0 只把敌军投影在路线尽头。表现层不得伪造敌军沿路线
移动。接敌状态由“小队到达路线距离且该路仍有敌军”派生。

## 画面结构

- 顶部：任务名称、中文战斗阶段、战斗刻、目标和剩余进度。
- 中央：两条真实路线、我方集结／撤离方向、敌军来向、障碍和敌军余量。
- 小队：战场标记显示队名与存活人数；点击后使用低饱和琥珀色高亮。
- 底部左侧：三支小队的部署路线、人数和状态。
- 底部中部：唯一选中小队及“推进／坚守／撤退”命令。
- 底部右侧：最近三条真实战况，包括命令提交、接敌、伤亡、敌军减少、障碍受损、
  粮车受损和斥候发现。

命令仍进入原 `BattleSession.issue_order()`，并在下一个固定 tick 生效。UI 不直接
改变小队位置、生命、敌军或任务目标。

V0 没有新增 Tween 或依赖动画时序；小队标记直接显示最近一次权威位置快照。后续若
增加短暂闪烁或插值，也只能表现已经发生的变化，不能成为伤害或结算条件。

## 三种任务投影

### 城郊清剿

两条路线均显示敌军数量和“据守／接战／已肃清”状态。敌军清零来自真实路线生命
归零，表现层不自行判胜。

### 粮道求援

中央显示固定粮车和真实生命条。无人小队在路线尽头拦截且该路仍有敌军时，粮车显示
受威胁；攻击方向从两条真实路线派生。

### 失踪斥候

发现前两条路线只显示同样的“搜索区？”，`revealed_route_id` 为空，不泄露任务定义
中的真实路线。发现后才标出找到斥候的搜索区，并持续显示左侧安全撤离区。

## 输入与退出

- 不新增 `_input`；C0 仍只用 `_unhandled_input` 接收 Esc。
- 小队标记和底部按钮使用 Godot `Control` 信号，不争抢城市原始输入。
- 选择不写 BattleSession，不产生 BattleOrder。
- 退出确认、全军撤退、结果确认、返回城市和窗口关闭沿用现有 C0-F 行为。
- 结果待确认后命令区禁用；重复点击不能绕过既有幂等保护。

## 布局基线

场景以 `1152 × 648` 为最低基线，主要区域使用横向伸展和底部锚定。自动布局断言
同时覆盖 `1280 × 720` 与 `1920 × 1080`，确保主战场、两条路线和底部命令区不
裁切。该检查不等于正式响应式 UI 或美术验收。

## 自动验证

`run_c0_battle_presentation_smoke.gd` 覆盖：

- 只读投影不改变 `BattleSession.get_state_digest()`；
- 选择只影响 UI；
- 两路线敌军、接敌与路线尽头投影；
- 粮车生命、危险路线；
- 斥候发现前隐藏、发现后揭示和撤离区；
- 点击小队标记与单一命令路径；
- 同 tick 重复命令拒绝；
- 无默认测试按钮、无第二个 `_input`；
- 三种分辨率的主要区域无裁切。

原 C0 事务、确定性演算、结果写回、安全退出、告示板流程及 P0/P1 回归必须继续
通过。

正式入口 GUI 检查同时发现告示板卡片仍直接显示 `AVAILABLE` 和结果摘要中的
`mission_id / RETREAT`。本切片只把这些已有状态映射为“可接受／进行中／已完成”
及中文任务名、胜利／失败／主动撤退；它不改变任务状态机。

## V0 限制与用户门禁

- 没有正式地形、角色、动画、音效或粒子。
- 敌军仍是路线尽头的聚合标记，不是单兵表现。
- 不新增转移路线、主动技能、工程师或复杂地形规则。
- 不修改 P1-F1A 空间内核，不开始 P1-F1B。
- 用户仍需实体判断：小队是否容易点选、三命令是否清楚、三类任务是否能一眼读懂、
  最近战况是否足以解释胜负。
