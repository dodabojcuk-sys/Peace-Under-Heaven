# P0-06 条件性下一组连贯功能包研究

## 状态更新：方向已推迟

本文原推荐方向：

`P0-06A_MINIMAL_PROTOTYPE_BUILDING_DEFINITIONS_AND_TWO_TEMPLATE_FLOW`

已被用户于 2026-07-25 提出的最新 UI 与建筑交互反馈推迟，不再作为当前 P0-06 的执行方向。

推迟原因：

- 建造入口仍错误占据底部临时操作栏；
- “派遣／管理”是没有真实职责的常驻占位；
- 当前六个预置建筑无法复用已验收的选择、描边和详情机制；
- 在建筑与 UI 职责尚未统一前增加第二模板，会继续扩大两套建筑体验之间的差异。

新的优先阶段为：

`P0-06_UNIFIED_BUILDING_INTERACTION_AND_RIGHT_SIDE_CONSTRUCTION_ENTRY`

正式范围见：

`docs/design/P0_06_UNIFIED_BUILDING_INTERACTION_AND_RIGHT_SIDE_CONSTRUCTION_ENTRY.md`

本文保留为历史研究证据；双模板验证可在统一建筑交互完成后重新评估，但当前不授权实现。

## 7. 唯一推荐方向

条件性推荐：

`P0-06A_MINIMAL_PROTOTYPE_BUILDING_DEFINITIONS_AND_TWO_TEMPLATE_FLOW`

中文范围：

**最小原型建筑定义 + 两种中性模板选择和放置。**

只增加第二种中性测试模板，用不同 footprint 验证当前权威记录、预览、占用、选择、详情和移除是否真正由模板数据驱动。

## 8. 推荐依据

1. 当前只有一个 3 x 2 常量，尚未证明不同 footprint 能走同一闭环。
2. P0-05 已把运行时实例数据集中到一个所有者，适合在其上验证少量定义数据。
3. `template_id` 已存在，但当前固定为一个值；下一步可以验证其真实用途。
4. 两种中性模板足以暴露重复常量、占用计算和详情显示问题。
5. 不需要资源消耗、生产、道路或存档。
6. 失败时可以删除第二模板和选择浮层，不影响 P0-05 生命周期。

## 9. 暂不选择另外方向的原因

### A. 建造体验进一步收束

当前进入、预览、确认、取消和连续放置已经闭环。只增加模式提示或退出按钮会改善清晰度，但不会验证当前最重要的数据扩展点，玩家价值也较弱。它可以作为双模板界面的附带可读性要求，但不应单独成为下一功能包。

### C. 道路连接与建筑启用

- 现有道路只是灰盒视觉，没有逻辑格或拓扑；
- 尚未决定道路由玩家建造、预制还是自动连接；
- “连接”和“启用”是两套状态；
- 很容易同时引入资源、入口方向、保存和城市规则；
- 若现在实现，可能把 40 单位原型格错误固化成正式道路合同。

道路应先有独立规则研究，不与下一轮双模板验证混合。

## 13. 建议状态模型

只扩展现有建造状态：

```text
IDLE
CHOOSING_TEMPLATE
PLACING
```

- `IDLE`：普通导航与建筑选择。
- `CHOOSING_TEMPLATE`：只显示两个模板选项；未选择时不创建预览。
- `PLACING`：沿用当前左键确认、中键拖动、滚轮缩放、右键或 Esc 取消。
- 选择模板后进入 `PLACING`。
- `Esc`／右键在 `CHOOSING_TEMPLATE` 返回 `IDLE`。
- 进入 `CHOOSING_TEMPLATE` 或 `PLACING` 均清除建筑选择和移除确认。
- 放置成功后保持同一模板的 `PLACING`，维持当前连续放置行为。

不建立全局状态机。

## 20. 风险和反例

### 定义与实例数据再次重复

反例：控制器常量、模板字典、节点 metadata 和记录各保存一份名称与 footprint。

控制方式：模板定义只在一个字典中；放置时把当时所需的运行时快照写入权威记录；节点只保留 ID。

### 模板浮层重新破坏 UI Shell

反例：增加全高侧栏或大型建造菜单，压缩地图。

控制方式：只允许两个选项的小型浮层；实现前先冻结位置和尺寸。

### 原型定义被误当成正式内容模型

反例：加入资源路径、等级、成本、产出和序列化版本。

控制方式：命名明确使用 `prototype`，只保存当前闭环需要的显示和 footprint 字段。

### 两种 footprint 破坏安全移除

反例：移除仍写死六格，导致 2 x 2 留下幽灵占用或误删相邻格。

控制方式：所有释放必须读取记录中的 `occupied_footprint_cells`，并为四格和六格分别断言。

- P0-06 实现必须保持独立、未验收前不提交；

## 22. 停止条件

出现以下任一情况停止：

- P0-05 尚未实体接受；
- 需要修改 `project.godot`；
- 需要第二个建筑记录、输入控制器、MapWorld、Camera2D 或 UI Shell；
- 需要资源、道路、升级、生产、存档或多城市数据才能继续；
- 两种 footprint 无法共用现有占用和移除合同；
- 模板选择 UI 无法在不明显压缩地图的情况下表达；
- 原导航、建造、选择或生命周期 smoke 回归；
- 用户希望直接定义正式建筑名称、成本或道路规则，但尚未完成独立研究。

## 23. Figma 与用户关键决策

### 是否需要 Figma

建议在编码前做一个很小的低保真 Figma 切片，只比较模板选择入口的两种表达：

1. 建造按钮上方的小型两项浮层；
2. 底部操作栏内的临时两项展开。

不需要重做整张地图 UI，也不设计正式建筑图标。

### 必须由用户决定的关键分叉

只保留一个：

> 模板选择使用“按钮上方浮层”还是“底栏内展开”？

推荐“按钮上方小型浮层”，因为不会挤占现有底栏，也不需要把“派遣／管理”占位误改成建造模板。

第二模板的 2 x 2 footprint 可以作为 P0 测试参数，不需要在正式尺度冻结前另行决策。
