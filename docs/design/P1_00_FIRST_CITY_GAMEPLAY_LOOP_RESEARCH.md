# P1-00 首个城市玩法闭环研究

## 1. 研究结论

本轮只研究，不实现。

推荐首个城市闭环：

```text
放置伐木场
→ 铺设道路接入城主府主路源
→ 伐木场从“未接通”变为“运行中”
→ 获得首批木材
→ 木材支持下一段道路或下一座伐木场
→ 玩家选择下一处扩张方向
```

推荐名称：

`ROAD_TO_LOGGING_CAMP_TO_WOOD_EXPANSION`

可接受备选：

`ROAD_TO_FARM_TO_FOOD_SUPPLY`

两者都能复用当前网格、placement、占用格、选择和详情结构。推荐方案的优势是奖励“木材”能直接支持下一段道路，因果链最短，不需要先实现军队、战役、人口或时间模拟。

当前状态为：

`P1_00_RESEARCH_COMPLETE_AWAITING_FIRST_LOOP_DECISION`

候选尚未获得用户确认，不得描述为已经授权实现。

## 2. 仓库事实

以下是当前仓库已经存在的事实：

- 唯一主场景是 `res://scenes/blank_map.tscn`。
- 唯一地图为 2200 x 1400 的 `MapWorld`，唯一相机为 `Camera2D`。
- `map_pan_controller.gd` 是唯一 `_input` 所有者。
- `ConstructionController` 是建筑记录、placement ID、占用格和运行时移除的唯一权威所有者。
- 固定建筑和运行时测试建筑使用同一记录形状。
- 当前逻辑网格为 40 世界单位；运行时测试建筑为 3 x 2 格。
- 场景中有两条 40 世界单位宽的灰盒道路，但它们只是视觉节点。
- 当前没有道路 placement、道路拓扑、主路源、建筑入口或连通算法。
- 当前没有资源账本、生产、建筑启停、正式建造目录、存档或多城市状态。
- 顶部只显示“粮食、木材、石料”的中性占位，没有真实数值。
- 固定建筑包括城主府、兵营、粮仓、学院、城门和军令台；它们目前只有灰盒身份和中性说明。
- P0 参数不是正式道路尺度、建筑 footprint 或存档合同。

仓库没有 README、独立 roadmap、DECISIONS 或 CHANGELOG。P0 文档只明确“道路与建筑启用需要独立研究”，没有冻结具体玩法。

## 3. 本文的设计判断

以下属于本研究提出、等待用户选择后才生效的设计判断：

- 首个闭环应先证明城市空间操作会产生真实收益。
- 第一种正式生产建筑优先选择“伐木场”。
- 道路以当前 40 单位网格作为 P1 实现参数，并采用四方向连通。
- 城主府周边的一组源格作为最小主路源。
- 连通状态从道路 placement 派生，不保存第二份可独立修改的道路真相。
- 首次连通给出一次明确的首批木材反馈，避免先引入时间系统。
- 木材用于下一段道路或下一座伐木场，从而形成自我推进的城市扩张循环。

具体初始资源、道路成本和首批木材数量是阶段内可调的原型参数，不需要用户逐项批准；若调整会改变闭环目标或引入付费／等待压力，则重新进入方向门禁。

## 5. 候选 A：伐木场、木材与道路扩张

### 5.1 玩家动作

1. 从现有右侧建造入口选择“伐木场”。
2. 在空地放置伐木场。
3. 选择“道路”，从城主府主路源向伐木场入口铺设连续格。
4. 最后一格接通后观察状态和资源反馈。

### 5.2 状态变化

```text
伐木场：未接通
→ 道路格形成到主路源的四向连通路径
→ 伐木场：运行中
→ 首批木材已领取
```

道路连通应是从 placement 记录派生的结果；不另存一份可手动写入的 `connected=true` 真相。

### 5.3 立即可见反馈

- 伐木场描边或状态色从中性未启用变为运行中。
- 详情面板显示“已接入道路”。
- 顶部资源摘要显示真实木材数值增加。
- 地图出现简短、非阻塞的“首批木材 +N”反馈。
- 下一段道路或下一座伐木场在建造目录中显示可承担。

### 5.4 下一次决策

玩家使用得到的木材决定：

- 向地图另一个方向铺下一段道路；
- 或积累后再放置一座伐木场。

这使“道路为什么值得建”与“为什么继续操作”使用同一种资源闭合，不要求战役或长期计时。

### 5.5 第一种正式可建对象

- 第一种正式基础设施：`道路`，1 x 1 格。
- 第一种正式建筑：`伐木场`，建议原型 footprint 为 2 x 2 格。

尺寸只是 P1 原型参数，不冻结为正式存档合同。

### 5.6 最少权威字段

在现有建筑记录上最少需要：

- `template_id`
- `placement_kind`：增加 `road`
- `origin_cell`
- `footprint`
- `occupied_footprint_cells`
- `road_anchor_offsets`
- `requires_road`
- `build_cost`
- `yield_kind`
- `yield_amount`
- `first_delivery_claimed`
- 既有 `selectable/removable/movable`

资源域最少需要一份唯一账本：

```text
wood: int
```

`operational_state` 和 `disabled_reason` 优先由 placement 与连通结果计算；若为 UI 缓存，不能成为独立可写权威。

### 5.7 与现有 placement 和占用格衔接

- 道路和伐木场都获得普通单调 placement ID。
- 道路使用同一 placement 记录与生命周期入口，不建立第二份道路对象列表。
- `_occupied_cells` 继续是空间占用权威。
- 道路格可通过 `placement_kind=road` 从 placement 记录派生。
- 伐木场入口由定义中的 anchor offset 换算成世界格。
- 固定建筑占用保持不变；主路源只是一组连接起点，不修改固定建筑身份。

### 5.8 是否需要资源账本、道路网络和启停

- 需要一个木材账本，且只能有一个所有者。
- 需要道路连通查询，但不需要持久化第二份图结构。
- 需要“未接通／运行中”和原因反馈。
- 不需要时间、生产队列、人口、耐久或升级。

建议职责边界：

- `ConstructionController`：继续独占 placement、建筑记录和占用格。
- P1 城市玩法控制器：只拥有资源账本、首批收益结算和派生连通结果，不复制 placement 或 occupancy。

选择推荐方案即授权建立这一新资源域；若实现要求复制建筑权威状态，则必须停止。

### 5.9 未来必须进入存档的状态

- 道路和伐木场 placement。
- 每个 placement 的模板、origin、footprint 和必要运行时进度标记。
- 木材余额。
- `first_delivery_claimed`，防止重载重复发放。

道路连通集合、运行中状态和禁用原因应在加载后重算，不进入权威存档。

P1 可以先保持内存态，但字段必须明确哪些未来需要持久化；本阶段不实现 schema 或迁移。

### 5.10 3–5 分钟实体测试

1. 进入建造目录，放置一座伐木场。
2. 确认它显示“未接入道路”，没有发放木材。
3. 铺设一条不连主路的孤立道路，状态不变。
4. 补齐到主路源的最后一格。
5. 观察伐木场立即变为运行中，木材只增加一次。
6. 使用木材开始下一段道路。
7. 删除或断开一格道路，伐木场变为停用但不重复扣除已发放木材。
8. 恢复连接，不重复领取首批奖励。
9. 确认地图导航、选择、详情和 UI 防穿透无回归。

### 5.11 后续兼容性

- 多城市：每城拥有独立资源账本和主路源，placement 合同可复用。
- 外城战役：木材可成为远征准备资源，但 P1 不实现。
- 建筑升级：以后可以增加产量或入口数量，不改变道路连通基本合同。

### 5.12 返工风险与暂不做

主要风险：

- 把当前 40 单位网格错误冻结为永久道路尺度。
- 把派生连通状态保存成第二份可写真相。
- 通过拆除／重建反复领取首批奖励。

暂不做：

- 定时产出、运输动画、道路方向贴图、路口美术。
- 道路成本平衡、多个资源、升级、存档和多城市。
- 建筑移动、批量铺路、连续工具、undo／redo。

## 6. 候选 B：农田、粮食与城市供给

### 6.1 玩家动作

放置农田，铺路接入城主府主路源，获得首批粮食或供给，再选择下一处农田扩张方向。

### 6.2 状态变化

```text
农田未接通
→ 道路连通
→ 农田运行中
→ 首批粮食入账
```

### 6.3 立即可见反馈

- 农田状态变为“已接入道路”。
- 顶部粮食数值增加。
- 详情说明粮食是后续城市供给和训练基础。

### 6.4 下一次决策

玩家可以继续连接第二块农田，或保留粮食给后续兵营。当前 P1 若不实现兵营消费，后一选择只能作为明确预告，闭环自我推进性弱于木材方案。

### 6.5 第一种正式可建对象

- 基础设施：道路。
- 第一种正式建筑：农田，建议 2 x 2 格。

### 6.6 最少权威字段

与候选 A 相同，但 `yield_kind=food`。若加入“供给容量”，还需要 `food_capacity` 或 `supply_capacity`，会扩大状态面。

### 6.7 与现有结构衔接

同样复用 placement、占用格、anchor 和派生连通；不需要第二套建筑系统。

### 6.8 系统需求

- 需要粮食账本。
- 需要道路查询和建筑启停。
- 若要让粮食立即有用途，还需要训练、人口消费或另一种建设成本。

### 6.9 未来存档

农田与道路 placement、粮食余额、首批收益标记需要保存；连通状态重算。

### 6.10 3–5 分钟实体测试

与候选 A 相同，将伐木场和木材替换为农田和粮食；额外检查粮食用途是否能被玩家理解。

### 6.11 后续兼容性

- 多城市与城市供给兼容性高。
- 与兵营、驻军和战役后勤的主题联系强。
- 升级可以提高粮食收益或容量。

### 6.12 风险与暂不做

最大风险是“获得粮食以后当前没有可执行用途”，玩家看到数值变化却没有下一步。若选择该方案，P1 必须至少给出一个真实可点击的下一处供给扩张选择，但仍不进入募兵或战役。

## 7. 候选 C：兵营、募兵与驻军

### 7.1 玩家动作

把道路接到现有兵营，解锁一次募兵或驻军操作。

### 7.2 状态变化

兵营从未接通变为可用，产生兵力或驻军容量。

### 7.3 立即可见反馈

兵营详情出现可用状态、兵力数字和一次真实操作。

### 7.4 下一次决策

玩家决定留守还是准备进入战役。

### 7.5 第一种正式可建对象

只需道路；兵营沿用当前固定建筑。

### 7.6 最少权威字段

除道路和启停外，需要单位数量、训练成本、驻军容量、训练状态和归属。

### 7.7 与现有结构衔接

道路仍可复用 placement，但兵力不属于建筑记录或 occupancy，需要独立军事权威状态。

### 7.8 系统需求

不一定需要生产建筑，但需要资源消费、军队状态和兵营操作。

### 7.9 未来存档

道路、兵营启用派生结果、训练进度、兵力和驻军归属都涉及存档。

### 7.10 3–5 分钟实体测试

接路、启用兵营、训练一次、观察兵力变化，并验证断路后的规则。这已经超出单一城市基础收益。

### 7.11 后续兼容性

对战役兼容性最高，但会过早把城市闭环绑定军事路线。

### 7.12 淘汰原因

当前没有单位、军事资源、驻军或战役入口。选择它会一次引入道路、建筑启用、资源消费和军事状态，触发重大架构与产品门禁，不适合第一个 P1 切片。

## 8. 为什么现在不先做建筑移动

建筑移动只改善空间编辑能力，不回答：

- 玩家为什么放这栋建筑；
- 建筑位置如何产生收益；
- 道路为什么重要；
- 操作完成后下一步是什么。

在道路、入口和收益规则尚未成立前实现移动，会先复杂化 occupancy 原子迁移、选择状态和取消规则，却没有新增玩法因果。移动应在首个闭环成立后单独研究。

## 9. 为什么现在不进入 Figma

- 当前右侧建造入口、模板列表和 280 x 360 详情面板已能承载一个建筑、道路和状态原因。
- 当前主要未知是玩法因果，不是页面信息架构。
- 先做 Figma 容易把未验证的成本、产出、道路工具和状态字段画成假功能。
- P1 原型可以使用现有灰盒 UI 验证“未接通 → 接通 → 收益 → 下一步”。

只有实现被迫新增页面、全高侧栏、复杂目录或明显压缩地图时，才触发用户信息架构门禁并回到 Figma。

## 10. 推荐 P1 连续实施包

用户选择闭环后，可一次授权以下四个里程碑。AI 在每个里程碑测试通过并形成原子提交后自动继续，不逐步等待批准。

### P1-01：正式最小目录与数据边界

范围：

- 在现有右侧建造入口中加入“道路”和所选生产建筑。
- 将单一测试模板整理为最小只读定义。
- 明确建筑记录新增字段和资源账本唯一所有者。
- 保持 P0 测试建筑兼容或完成一次范围内迁移，不建立第二份记录。

禁止：

- 道路连通、收益、正式美术、存档和多城市。

数据变化：

- 增加定义字段、`placement_kind=road`、anchor、成本和收益声明。
- 不替换 placement ID 或 occupancy 权威。

自动验收：

- 定义唯一、ID 唯一、不同 footprint 正确、现有 P0 smoke 全通过。

回滚点：

- `P1-01` 原子提交。

自动继续条件：

- 没有第二份建筑记录；旧闭环全部通过。

必须停止：

- 需要 Resource 数据库、依赖或正式存档 schema 才能表达两个对象。

### P1-02：道路放置与连通判断

范围：

- 1 x 1 道路 placement。
- 从主路源进行四方向 BFS。
- 生产建筑 anchor 与连通原因查询。
- 孤立道路、断路和恢复连接。

禁止：

- 自动寻路、弯道美术、批量铺路、拖拽连续工具和资源收益。

数据变化：

- 道路仍是统一 placement。
- 连通集合为派生结果，不新增可写道路图。

自动验收：

- 孤立道路不连通、最后一格接通、断开失效、恢复有效、固定占用与 UI 遮挡继续成立。

回滚点：

- `P1-02` 原子提交。

自动继续条件：

- 连通结果可从 placement 完整重算。

必须停止：

- 需要第二份道路真相、非网格拓扑或修改现有 Camera2D／输入合同。

### P1-03：建筑启停与原因反馈

范围：

- 建筑显示“未接入道路／运行中”。
- 地图选择反馈和详情原因同步。
- 道路移除或恢复后状态立即重算。

禁止：

- 收益结算、时间、升级、人口和正式 UI 重做。

数据变化：

- 启停优先作为派生查询；不复制到第二份状态。

自动验收：

- 同一 placement 的地图反馈、详情和连通结果一致；P0 选择、移除和导航无回归。

回滚点：

- `P1-03` 原子提交。

自动继续条件：

- 玩家可在现有 UI 中看懂未启用原因。

必须停止：

- 必须新增页面或改变已冻结的信息架构才能表达原因。

### P1-04：一次真实收益与下一次城市决策

范围：

- 建设成本和所选资源的一份真实账本。
- 第一次接通只结算一次首批收益。
- 收益足以支持一个明确的下一次城市扩张操作。
- 完整自动回归和最终实体测试准备。

禁止：

- 定时生产、生产队列、资源交易、升级、存档、多城市、军事和战役。

数据变化：

- 资源余额和防重复结算标记。
- 明确未来需保存的字段，但本阶段不实现存档。

自动验收：

- 未接通无收益；首次接通结算一次；断开／恢复不重复发放；资源不足拒绝且不产生部分写入；下一操作可承担。

回滚点：

- `P1-04` 原子提交。

自动继续条件：

- 全部 smoke、editor scan、场景启动和 diff 检查通过。

必须停止：

- 收益必须依赖时间系统、军事系统、第二套资源账本或未授权 UI 才能闭环。

### 最终用户体验门禁

P1-01 至 P1-04 完成后，AI 保持可运行窗口并一次性提交实体测试清单。用户只在此处判断：

- 是否明白为什么铺路；
- 接通反馈是否足够直接；
- 收益是否让下一步自然出现；
- 3–5 分钟内是否形成可理解、愿意继续的城市闭环。

通过后再更新 accepted 状态和推送阶段基线。

## 11. 整阶段禁止范围

- 建筑移动、批量操作、连续铺路工具和 undo／redo。
- 正式美术、动画、音效和完整 UI 重做。
- 多城市、战役、派兵、军令台功能和军事玩法。
- 建筑升级、人口、耐久、生产队列和时间模拟。
- 正式存档 schema、迁移和兼容层。
- 第二套 MapWorld、Camera2D、输入所有者、建筑记录或 UI Shell。

## 12. 一次授权后的执行方式

用户选择推荐或备选闭环后，可以一次授权整个 P1 包：

```text
P1-01 数据与目录
→ P1-02 道路与连通
→ P1-03 启停与原因
→ P1-04 收益与下一决策
→ 自动验收
→ 用户实体体验门禁
```

AI 在阶段内负责读仓库、拆分、编码、测试、修复、文档和本地原子提交。只有触发 `docs/process/PROJECT_EXECUTION_GATES.md` 中的停止条件，或形成完整可运行闭环，才返回用户。
