- 目的：冻结 P1 第一张地图的完整玩家循环、V0 数值边界、失败路径和连续实施范围。

- 第一个技术切口：`伐木场 → 道路接通 → 木材`。

```text

→ 自动时间推进／明确暂停

```

本文所有数值都是首轮校准值。用户实体测试后可以在约 `±15%` 范围内调整；调整不得静默改变玩家目标、日期压力结构、权威状态或胜负规则。

## 2. 仓库事实与设计判断

### 2.1 文档起草时的仓库事实（历史）

- 当前唯一主场景为 `res://scenes/blank_map.tscn`。
- 当前唯一地图为 `MapWorld`，唯一相机为 `Camera2D`。
- `map_pan_controller.gd` 是唯一 `_input` 所有者。
- `ConstructionController` 是 placement、建筑记录、占用格和运行时移除的唯一权威所有者。
- `BuildingSelectionController` 只拥有 `selected_placement_id`，不复制建筑记录。
- 当前地图中的道路只是视觉节点，不是道路 placement 或连通网络。
- 当前没有资源账本、日期、生产、军队、科技、威胁时间线、关卡定义或存档。
- 当前固定建筑恰好六个：

| 节点 | 当前显示名 |
| --- | --- |
| `Manor` | 城主府 L1 |
| `Barracks` | 兵营 L1 |
| `Granary` | 粮仓 L2 |
| `Academy` | 学院 L1 |
| `CityGate` | 城门 L1 |
| `CommandPlatform` | 军令台 L1 |

仓库不存在“告示板”固定建筑。本文不得据此新增、重命名或替换任何场景节点。

### 2.2 本文提出的 V0 设计

- 道路采用网格 placement，并从城主府道路根节点派生四方向连通关系。
- 道路放置后即时完成；伐木场、农田、仓库和瞭望塔使用当前 P1-F V0 的一日施工期。标记为 `requires_road` 的生产能力还必须接入城主府道路网络。
- 城市时间默认自动流动，玩家只能明确暂停或继续；正式玩法不存在“结束本日”入口。
- `ConstructionController` 以受控模拟增量累计当天进度，日界线仍是唯一、离散且确定的结算点。
- 当前 `SECONDS_PER_DAY = 180` 是便于规划的临时 V0 节奏参数，只等待真人体验校准，不是最终平衡。
- 暂停只冻结城市模拟时间；地图导航、建筑查看、建设规划和普通 UI 继续可用。
- 系统墙钟、离线追赶、窗口焦点和普通面板都不得改变时间或暂停状态。
- 敌军强度、下一次骚扰和下一次增援始终公开。
- 第 12 日是当前最后一个已定义特殊事件日，但不会自动暂停或停止城市时间；第 13 日以后继续通用城市结算，不新增未定义的特殊事件。
- 第一张地图先用确定性的战备校验闭合攻关结果；它是纵向切片的平衡代理，不是永久战斗公式。

## 3. 玩家目标和 3～5 分钟核心体验

玩家需要理解三个因果：

1. 为什么建路：生产建筑只有接入城主府道路网络才会在下一日结算。
2. 接通后得到什么：伐木场产木材、农田产粮食，资源可以继续扩张、募兵或加强防御。
3. 为什么需要及时决策：敌军会在公开日期骚扰并增强，第 12 日达到当前已定义威胁峰值；时间仍继续流动，后续特殊内容尚未扩展。

一次最短体验应能覆盖：

```text
放置伐木场
→ 铺路接通
→ 等待自动日界线（可暂停规划）
→ 获得木材
→ 选择继续扩张、补粮、加强城防或募兵
→ 观察下一次敌军压力
```

完整首图体验再加入科技、将领选择、提前进攻和极限日战备。

### 5.1 放置与道路规则

- 道路和建筑都进入现有统一 placement 记录，不建立第二份道路对象列表。
- 道路连通从 placement 和占用格派生，不保存可独立写入的 `connected=true`。
- 城主府提供一个固定的道路根节点或根格集合。
- 道路采用四方向连通；斜角接触不算接通。
- 生产建筑通过定义中的道路锚点连接道路。
- 道路即时完成；其余当前可建建筑在下一次日期结算完成，施工中不提前提供生产、容量或城防效果。
- 道路断开后，建筑从下一次结算起停产；已入账资源不回滚。
- 恢复道路后，从下一次结算恢复，不补发断开期间产量。
- 道路连通、运行状态和停用原因是派生结果，未来加载时重算。

## 7. 日期结算顺序

玩家在本日可以自由建造、铺路、研究、训练和整备。城市时间默认运行；到达唯一日界线后，按固定顺序进入下一日：

1. 校验是否存在战斗事务锁；第 12 日及以后不构成日期推进限制。
2. 完成到期施工；施工中的生产、容量与城防效果此前均不生效。
3. 扣除军队维护粮食。
4. 完成上一日下达、且仍满足容量的训练批次。
5. 对当前接入道路、未被事件停产的已完工生产建筑结算产量。
6. 学院增加 1 科技点。
7. 更新目标日的敌军人数和工事。
8. 结算目标日骚扰或事件。
9. 清除已经完成的一日停产标记。
10. 显示当前日、下一次骚扰、下一次增援和可行动状态。

若维护粮食不足：

- 粮食降到 0；
- 不产生负数；
- 本日军队进入“供给不足”，攻击战备评分降低 10%；
- 不删除士兵，不静默产生债务；
- 下一日补足粮食后恢复。

这一条是防止资源不足直接破坏运行态的 V0 护栏，仍需实体测试校准。

## 11. 提前进攻、极限日和战备校验

### 11.1 提前进攻

- 第 1～11 日都允许从军令台发起攻击。
- 发起前显示己方步兵、将领、科技修正、敌军人数、工事和战备评级。
- 玩家可以选择提前冒险，或继续发育并承受后续骚扰和敌军增强。

### 11.2 P1 纵向切片的平衡代理

P1-F 自动平衡只使用确定性代理，不将其写成永久战斗系统：

```text
己方战备 = 步兵人数 × 攻击修正 × 供给修正
敌方战备 = 敌军人数 × (1 + 工事等级 × 0.10)
战备比 = 己方战备 / 敌方战备
```

- `战备比 >= 1.00`：优势窗口。
- `0.85 <= 战备比 < 1.00`：高损胜利窗口。
- `战备比 < 0.85`：预计失败。

先锋官和“队列操练”按乘法叠加攻击修正。供给不足时供给修正为 `0.90`，否则为 `1.00`。

这个公式只用于验证“提前、推荐、极限日期至少有一个合理通关窗口”。若未来加入真实战斗，胜负与伤亡由独立获批的战斗规则替换；不得让两套公式同时成为运行时权威。

### 11.3 第 12 日内容边界与防死档

第 12 日：

- 城市时间继续运行，并可进入第 13 日及以后；
- 此后继续通用日结算，但当前没有新增特殊事件；
- 允许调整军队和将领；
- 允许使用已有资源；
- 允许研究当前能承担的科技；
- 允许发起攻击；
- 允许一次紧急动员；
- 允许回到第 9 日自动战备检查点；
- 允许重开本图。

紧急动员 V0：

- 每局仅一次；
- 消耗 30 粮食；
- 立即增加 5 名步兵；
- 允许临时超过征募上限 5 人；
- 不产生可重复领取或跨检查点复制的部队。

第 9 日检查点必须包含城市运行态、placement、资源、军队、科技、日期和首次奖励标记。P1 本轮不实现正式存档；实现检查点时若需要正式 schema 或迁移，触发执行门禁并停止。

## 12. 失败路径

### 12.1 资源不足

- 建造、铺路、训练和紧急动员均原子拒绝。
- 不产生负资源、半个建筑或部分道路。
- UI 明确显示缺少哪种资源和数量。

### 12.2 道路断开

- 建筑保持存在，但显示停用原因。
- 下一日不生产。
- 已结算资源不回滚，重新接通不补发。

### 12.3 城防不足

- 按公开时间线损失资源或停产。
- 资源损失最低为 0，不产生债务。
- 生产建筑停产目标在日界线前可预览。

### 12.4 提前进攻失败

- P1 的确定性战备代理必须在确认前给出“预计失败”警告。
- 玩家仍确认失败时，本局分支结束，可返回最近自动战备检查点或重开本图。
- 不允许失败后回到原日并保留已知结果、奖励或消耗形成复制漏洞。

### 12.5 极限日无法取胜

- 日期不再推进，不执行基地大清洗。
- 玩家可整备、紧急动员、攻击、回到第 9 日检查点或重开。
- 首图必须通过自动模拟证明至少存在提前、推荐和极限三个可通关窗口；否则 P1-F 必须停止，不能靠降低测试标准封存。

## 13. 首通、重打和历史状态

- 首通永久奖励只能领取一次。
- 重打不得重复修改正史和城市永久状态。
- 当前主战目标由军令台进入。
- “历战”只是一项后续内容入口规划；当前仓库没有告示板，不在 P1-A～P1-F 创建假入口。
- `RewardDefinition` 必须区分 `first_clear` 与 `replay`，并由唯一的关卡进度权威状态执行幂等校验。

## 14. P1 连续实施包

用户接受本文后，可以一次授权 P1-A～P1-F。AI 在阶段内完成实现、自动测试、修复、文档和本地原子提交，不在低风险工程细节上重复等待。

### P1-A：定义层、道路、伐木场和木材闭环

- 范围：类型化定义最小子集、道路 placement、四向连通、伐木场、木材账本、成本和下一日产出。
- 禁止：粮食、日期事件、军队、科技、战役、正式存档。
- 回滚点：一个原子提交。
- 自动验收：孤立道路、接通、断开、恢复、单一资源账本、P0 回归。

### P1-B：农田、粮食和日期结算

- 范围：农田、粮食、容量、自动时间／暂停、固定结算顺序、学院每日科技点的最小数据入口。
- 禁止：骚扰、战斗和完整科技 UI。
- 回滚点：一个原子提交。
- 自动验收：次日产出、容量、维护顺序、断路停产、日期不可重复结算。

### P1-C：骚扰、敌军增长和最后已定义威胁日

- 范围：`ThreatSchedule`、公开预警、城防阈值、资源损失、单建筑停产、第 12 日内容边界和防死档入口。
- 禁止：隐藏随机惩罚、系统墙钟／离线追赶和基地大清洗。
- 回滚点：一个原子提交。
- 自动验收：第 5／8／10／12 日顺序、达标／不足分支、目标确定性，以及第 12 日后通用时间继续且特殊事件不重复。

### P1-D：步兵、将领和最小科技

- 范围：兵营每日一批、维护、一个将领槽、首图 2～3 科技节点、紧急动员。
- 禁止：四兵种实装、装备随机化和完整军队编成。
- 回滚点：一个原子提交。
- 自动验收：成本、上限、每日批次、维护、科技效果和紧急动员幂等。

### P1-E：军令台攻击入口和首图串联

- 范围：军令台战备展示、提前进攻、`LevelDefinition`、检查点契约和首图结果串联。
- 禁止：正式战斗系统、告示板／历战 UI、多关卡生产和正式存档迁移。
- 回滚点：一个原子提交。
- 自动验收：引用有效、结果幂等、首通／重打隔离、检查点不复制收益。

### P1-F：自动验收、平衡模拟和实体体验门禁

- 范围：完整 smoke、配置校验器、三类通关窗口模拟、调试预览、用户实体测试清单。
- 禁止：为通过测试静默改变日期压力、胜负规则或核心玩法。
- 回滚点：验证与文档原子提交。
- 自动验收：全部 P0 回归、P1 集成、`git diff --check`、无缺失引用、无第二套权威状态。
- 用户门禁：首图是否好玩、日期压力是否舒服、玩家何时愿意进攻、反馈是否易懂。

## 15. 自动继续与停止条件

同一授权内满足以下条件可自动继续：

- 当前里程碑范围内测试通过；
- 完整 diff 与范围一致；
- 没有未知修改、依赖变化或第二套权威状态；
- 形成可回滚的本地原子提交；
- 下一里程碑没有触发用户体验门禁。

出现以下情况必须停止：

- 需要第二套运行时权威状态；
- 需要新依赖、正式存档 schema 或迁移；
- 数值模拟不存在合理的提前、推荐或极限通关窗口；
- 需要改变本文确定的日期压力、极限日护栏或军令台入口；
- 自动测试无法在阶段范围内收敛；
- 实际手感、难度或是否好玩必须由用户判断；
- 远端 behind、diverged 或需要改写历史。
