# P1-F 建设数据化 V0

## 1. 状态与边界

- 状态：`IMPLEMENTED_AWAITING_USER_GATE`
- 本文只冻结 P1-F 的第一个实施切片：建设信息、施工日界线和首战准备预测。
- P1-E 的场景与事务技术闭环成立，但产品体验尚未通过；按钮可用、状态可跳转和自动测试通过不能替代首战可玩性。
- P1-F 的完整顺序仍是：

```text
建设数据化
→ 建设结果影响首战
→ 正式北坡战场
→ 战果清楚回写
→ 真人体验与平衡
```

本文没有完成正式北坡战场、战斗表现重做或最终平衡。

## 2. 实现前审计

### 2.1 仓库已有的可建定义

| 定义 | 已有成本 | 已有效果 | 已有前置 |
| --- | ---: | --- | --- |
| 道路 | 木材 2 | 接通城市路网 | 空闲网格 |
| 伐木场 | 木材 40 | 木材 +18／日 | 接入道路后运行 |
| 农田 | 木材 45 | 粮食 +22／日 | 接入道路后运行 |
| 仓库 | 木材 60 | 木材、粮食容量各 +120 | 无道路要求 |
| 瞭望塔 | 木材 50 | 城防 +10 | 无道路要求 |

这些成本和效果在本轮前已经由类型化 `BuildingDefinition` 与 `BuildingCapability` 承载。本轮没有创建第二套数值表。

### 2.2 仓库已有的固定设施

固定设施只有城主府 L1、兵营 L1、粮仓 L2、学院 L1、城门 L1、军令台 L1。

- 兵营已有真实规则：每批征募 5 人、消耗 15 粮食、下一日完成。
- 粮仓已有真实规则：基础木材／粮食容量各 160。
- 学院已有真实规则：每日科技点 +1。
- 城门已有真实规则：基础城防 10。
- 军令台已有首战情报和入口。

固定设施的效果此前来自 `ConstructionController` 的既有权威规则，而不是独立建筑定义。本轮只把这些真实规则暴露到统一详情面板，没有复制第二套可写状态。

### 2.3 实现前缺口

- 可建按钮只有硬编码名称和简短说明。
- placement 在确认后立即进入运行态，没有施工进度或预计完成日。
- 统一详情面板主要显示类型、网格和占地，没有投资、效果和前置。
- 没有任何 L2／L3 静态定义，因此不存在可诚实展示的升级成本或升级收益。
- 第 6 日军令台显示战斗事务数据，但没有把当前兵力、粮草和城防整理成可读的准备短板。

## 3. V0 建设规则

### 3.1 等级与升级

- 现有五个可建定义明确为 L1。
- 固定设施继续使用场景中已经存在的等级。
- 仓库没有下一等级定义，所以详情明确显示“下一等级：当前切片未开放”。
- 本轮不提供升级按钮，不伪造 L2 成本、工期或效果。

### 3.2 施工时间

| 对象 | V0 工期 |
| --- | ---: |
| 道路 | 即时 |
| 伐木场 | 1 日 |
| 农田 | 1 日 |
| 仓库 | 1 日 |
| 瞭望塔 | 1 日 |

“1 日”是 P1-F 首轮可逆校准值，不是正式平衡或存档兼容承诺。施工在唯一城市日界线完成，不建立实时计时器或第二套施工队列。

资源在确认 placement 时原子扣除；施工中节点占用真实网格，但不提前提供生产、容量或城防效果。到达预计完成日后，记录从 `constructing` 变为 `running`，同一日结算按现有顺序启用效果。

### 3.3 权威记录

现有 placement 记录增加：

- `level`
- `next_level_definition_id`
- `build_wood_cost`
- `build_food_cost`
- `build_days`
- `construction_started_day`
- `construction_complete_day`
- `lifecycle_state = constructing / running`

上述字段继续由 `ConstructionController` 单一持有。地图标签、详情面板、容量、生产和城防都从同一记录与静态定义派生。

## 4. 玩家可见信息

### 4.1 建造目录

每个入口显示：

- 名称与当前等级；
- 真实成本；
- 工期；
- 真实效果；
- 道路前置；
- 当前资源不足原因。

资源不足时入口直接禁用并显示缺口，不允许玩家进入一个注定无法确认的预览。

### 4.2 建筑详情

统一详情面板显示：

- 当前等级；
- 下一等级是否开放；
- 已投入成本；
- 工期；
- 当前真实效果；
- 前置条件；
- 施工进度和预计完成日；
- 当前运行、断路、停产或施工原因。

地图中的施工建筑同时显示“施工中”和完成日，不能只靠详情文字证明状态变化。

## 5. 三类真实决策与首战因果

| 方向 | 当前真实操作 | 城市状态变化 | 当前对首战的真实影响 |
| --- | --- | --- | --- |
| 资源 | 建伐木场、农田、仓库并接路 | 木材／粮食日产或容量变化 | 支撑征募、建设和正式出战粮草 |
| 军事 | 使用固定兵营征募 | 步兵与维护粮食变化 | 改变可出战兵力和粮草需求 |
| 防御 | 建瞭望塔 | 完工后城防 +10 | 改变第 5 日骚扰减损与首战准备短板 |

军令台准备评估只使用当前真实字段：

- 当前可出战兵力与当前敌军；
- 当前粮食与正式出战粮草需求；
- 当前城防与已存在的首轮骚扰减损阈值。

它不显示未经真实战斗模拟支持的“胜率”，也不声称瞭望塔已经直接改变 C0 的城门 HP。建设结果进一步映射到正式北坡战场仍属于下一实施切片。

## 6. 自动验收

- 可建定义的成本、效果、等级和工期来自现有 Resource。
- 施工确认原子扣款并进入唯一 placement 记录。
- 施工中不提前获得生产、容量或城防效果。
- 日界线完成施工且只完成一次。
- 完工后生产、容量和城防从同一权威记录生效。
- 统一详情显示等级、投入、工期、效果、前置、进度和预计完成日。
- 无下一等级定义时不出现伪升级入口。
- 资源不足显示原因并禁用入口。
- 既有 P0／P1／C0 回归不退化。

## 7. 用户体验门禁

用户仍需实际判断：

1. 建造目录是否能在操作前看懂代价和收益。
2. 一日施工是否过快、过慢或缺乏反馈。
3. 施工中与已完工状态是否一眼可区分。
4. 军令台的兵力、粮草、城防短板是否足以指导第 1～6 日决策。
5. 建设选择是否开始形成经济、征募和防御之间的取舍。

通过该门禁后，下一实施切片才把这些真实建设字段映射进正式北坡战场。外城、正式美术、完整升级树和新建筑仍不在范围内。
