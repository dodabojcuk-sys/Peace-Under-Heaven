# 项目执行门禁

## 目的

本规则用于把“产品方向决定”和“阶段内工程执行”分开：

```text
方向门禁
→ AI 连续实施
→ 自动验收
→ 用户实体体验门禁
→ 阶段封存
```

用户负责核心玩法、重大方向和真实体验判断。AI 在已授权阶段内负责把方案连续推进到可运行、可回滚、可验收的状态，不退化成每个函数、测试或小提交都等待用户批准。

## 事实与权限原则

1. 真实仓库、真实运行窗口和用户实体操作高于文字汇报。
2. 自动测试是工程证据，不替代“是否好玩、是否易懂、手感是否正确”的用户判断。
3. 每类业务状态只能有一个权威所有者；派生索引和视图不得成为第二份可独立写入的真相。
4. 阶段授权只覆盖明确范围，不自动扩展到相邻系统、正式发布或不可逆操作。
5. 低风险工程选择由 AI 负责；会改变玩家目标或未来数据合同的选择进入用户门禁。

## 用户必须参与的门禁

出现以下事项时必须由用户决定或验收：

1. 首个或新的核心玩法闭环选择。
2. 会改变玩家目标、主要操作方式、信息架构或游戏节奏的方向。
3. 第二套权威状态、核心数据模型替换、正式存档 schema 或数据迁移。
4. 新依赖、重大架构分叉、跨阶段重排或高成本返工风险。
5. 可运行版本的实体操作，以及“是否好玩、是否易懂、反馈是否足够”的判断。
6. 阶段接受、范围扩大、远端发布、构建分发和正式部署。
7. 不可逆操作或会影响外部用户、数据、账号和线上环境的操作。

用户不需要逐项批准函数命名、helper 拆分、测试 fixture、文档位置、类型标注或同等低风险实现细节。

## AI 可在已授权阶段内自主完成

只要没有触发停止条件，AI 可以连续完成：

1. 仓库检查、设计查重、事实核验和依赖关系分析。
2. 将已授权阶段拆成可回滚的实现里程碑。
3. 低层数据结构、函数边界、节点连接和测试策略选择。
4. 编码、自动测试、局部修复和不改变产品方向的低风险重构。
5. smoke、静态检查、运行截图、完整 diff 审查和文档更新。
6. 阶段内原子提交和明确 checkpoint。
7. 测试失败时在当前范围内诊断、修复、补充断言并重新验证。
8. 类型完善、重复代码整理、死代码删除和测试可读性改进。
9. 已授权阶段内必要的状态文档、研究记录和验收材料维护。

AI 应选择最小、可维护、与现有架构一致的实现，不因“以后可能有用”建立未被当前闭环需要的框架。

## AI 必须停止的条件

出现以下任一情况，AI 必须保留现场并汇报，不得自行扩大修复：

- 工作区出现无法归属的未知修改。
- 核心文档与实际代码或运行事实无法调和。
- 实现需要第二份可独立写入的权威状态。
- 需要修改已冻结的核心玩法、输入合同或玩家目标。
- 需要引入依赖、替换核心数据模型或迁移存档。
- 自动测试持续失败且根因无法在当前范围内收敛。
- 安全修复必须扩大到当前授权阶段之外。
- 远端出现 behind、diverged，或操作需要改写历史、force push。
- 需要删除、覆盖、迁移或发布不可轻易恢复的数据。
- 最终结论必须依赖用户的主观体验判断。
- 当前实现只能通过伪造输入、绕过真实入口或降低验收标准才能通过。

停止时应说明：已确认事实、阻断点、已尝试的范围内方法、继续所需的用户决定或新授权。

## 阶段授权包

一个可以交给 AI 连续实施的阶段包必须写清：

- 玩家闭环和成功条件；
- 允许范围与禁止范围；
- 权威数据所有者；
- 里程碑及每个回滚点；
- 自动验收命令；
- 用户最终实体测试清单；
- 可自动继续的条件；
- 必须停止的条件；
- 提交、push、发布和部署权限。

只要这些边界清楚，AI 不在里程碑之间重复请求批准。

## 自动继续规则

满足以下条件时，AI 可自动进入同一授权阶段的下一里程碑：

1. 当前里程碑范围内实现完成。
2. 适用测试和 `git diff --check` 通过。
3. 没有未知修改、依赖变化或第二套权威状态。
4. 完整 diff 与授权范围一致。
5. 已形成可回滚的原子提交。
6. 下一里程碑没有触发用户门禁。

自动继续不等于自动扩大范围。

## 验收和证据边界

- 代码存在、测试通过和真实用户体验是三种不同状态。
- 自动构造事件只证明代码路径，不证明实体鼠标、键盘或触控板体验。
- 截图只能证明截图中可见的结果，不能推断未展示的完整流程。
- 用户总体接受不能被扩写成未提供的逐项观察。
- 阶段只有在自动验收完成并经过要求的用户体验门禁后，才能标记为 accepted。

## Git 与阶段收尾

- 每个独立里程碑形成一个职责明确的原子提交。
- 提交前审查完整 diff，不混入无关 dirty changes。
- 删除临时诊断、截图、缓存和取证残留。
- 更新 `CURRENT_STATE.md`；重大决策更新已有的决策或设计文档。
- 不把 `git stash` 当作长期备份。
- 远端 push、tag、Release、PR、发布和部署仍以阶段授权为准。
- 远端 behind 或 diverged 时停止，不擅自 merge、rebase、reset 或 force push。

## 本项目的长期协作方式

用户负责：

- 核心玩法与重大方向；
- 真实操作体验；
- 阶段验收和范围扩大。

AI 负责：

- 阶段内读仓库、拆任务、编码、测试、修复、整理、文档和原子提交；
- 把真正需要产品判断的问题收敛到最少；
- 在触发正式停止条件前持续推进，而不是逐条等待操作许可。
